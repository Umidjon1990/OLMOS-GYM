---
name: Orval inline requestBody schema conflict
description: When OpenAPI DELETE/POST endpoints use inline requestBody schemas (not $ref), Orval generates duplicate exports causing TS2308.
---

## Rule
Always use `$ref: "#/components/schemas/SomeName"` for requestBody schemas in OpenAPI spec. Never define them inline.

**Why:** Orval generates both a Zod const (in `generated/api.ts`) and a TypeScript interface (in `generated/types/`) for any inline body schema. Both get named after the operation (e.g., `BulkDeleteSubscribersBody`), and the barrel `index.ts` (regenerated by Orval) re-exports both → TS2308 "already exported" error.

**How to apply:** Any time you add a new endpoint with a requestBody, first add the schema to `components/schemas` in openapi.yaml, then reference it with `$ref`. This ensures the Zod const and TS type get different names (operation-derived vs schema-derived).

## api-zod/src/index.ts
Orval regenerates this file on every codegen run. Do not manually edit it to fix conflicts — fix the OpenAPI spec instead.
